# Slice 9 plan: PQC — ML-DSA, ML-KEM, SLH-DSA (28 rows)

ML-DSA LANDED (this commit; rest pending): `CKM_ML_DSA`
sign/verify + `CKM_ML_DSA_KEY_PAIR_GEN` over provider
one-shot DigestSign/Verify, all three levels × all
three hedges × pure/context, wycheproof KATs green.
Corrections to the discovery below (verified during
the vertical, kept as the record): keygen takes NO
mechanism parameter (the set rides the public
template); NULL serves pure (the struct is optional);
there is no `CK_ML_DSA_PARAMS` (the struct is
`CK_SIGN_ADDITIONAL_CONTEXT`); the shim cross-checks
the keymgmt type NAME (provider ML-DSA keys report
base_id 0); import assembles FLAT expanded-key PKCS#8
(the provider's own SEQ{seed,expanded} form is what
keygen stores — the two shapes differ by design).

## Discovery (evidence, not guesses)

- Provider (pinned OpenSSL 4.0.2) serves all three
  families: `ML-DSA-44/65/87`, `ML-KEM-512/768/1024`,
  12 `SLH-DSA-*` parameter sets
  (`openssl list -signature-algorithms` /
  `-public-key-algorithms`). No `HashML-DSA` /
  `HashSLH-DSA` signature entries listed — prehash
  support must be PROBED (EVP_DigestSign with a set
  digest? staged hash + raw? or unserved), never assumed.
- OASIS v3.2 wiring: parameter sets are `CK_ULONG`
  (`CK_ML_DSA_PARAMETER_SET_TYPE` etc.,
  `CKP_ML_DSA_44/65/87`, `CKP_ML_KEM_512/768/1024`, 12
  `CKP_SLH_DSA_*`), carried on keys/templates by
  `CKA_PARAMETER_SET` (0x61D); keygen mechs take NO
  mechanism parameter (verified against the OASIS
  working docs + p11-kit: the set comes from the
  public-key template). `CKM_ML_DSA` context is
  OPTIONAL (OASIS v3.2 §ML-DSA Signature): NULL
  params serve pure (hedge-preferred, empty context)
  — the opposite of EdDSA.
- Oracle scope (~2207 skipped in KAT r14): wycheproof
  mldsa (631) + context (21) + sign (220), CCTV mldsa
  (449), ACVP mldsa/mlkem/slhdsa (415/180/84),
  wycheproof mlkem (27) + encaps-modulus (36),
  hash_ml_dsa (45) + hash_slh_dsa (42), kem (29) +
  mech_kem (2) + ckr_kem (4), pqc_sign (21),
  mldsa_missing_param_set (1). Ranked inside the slice:
  ML-DSA first (1781), ML-KEM second (278), SLH-DSA
  third (126).
- `CKM_HASH_ML_DSA` (generic) requires
  `CK_HASH_SIGN_ADDITIONAL_CONTEXT` and is single-part
  only; the 10 hash-specific variants are single- plus
  multi-part. Same split for SLH-DSA (11 rows each).
- `CKM_ML_DSA_EXTERNAL_MU[_GEN]` are oracle-only
  (absent from the OASIS 3.2 header), out of scope.
- ML-KEM rides the v3.2 KEM API (`C_EncapsulateKey` /
  `C_DecapsulateKey`), not sign/verify. Model layer
  exists (`Operation/Kem.hs`: `planKemEncaps` /
  `planKemDecaps`, deterministic ct lens, 32-byte ss);
  Synthetic has `kemEncapsulate`/`kemDecapsulate` arms;
  OpenSSL4 has NO Raw KEM entry yet (catalog note) —
  that plus `GenMLKEM` wiring is the KEM work.
- Context strings: ML-DSA takes an explicit context
  (wycheproof context file, 21 legs) — unlike EdDSA,
  context is SERVED, not refused. Prehash/context
  domain separation is FIPS-204-native, not DIY.

## Design (mirror DSA/EdDSA precedent)

- Recipes `Recipe/MlDsa.hs` (LANDED), `Recipe/MlKem.hs`,
  `Recipe/SlhDsa.hs`: one row-group each; codecs
  `mldsa-params/1` (hedge word + length-prefixed
  context; the LEVEL rides the key, never the params
  — empty defaults preferred+empty),
  `slhdsa-params/1`, KEM parameter-set codec;
  `HASH_*` rows stay catalog-only (probe 1).
- `Der.hs`: PQC SPKI/PKCS#8 assembly (algorithm OID +
  raw key bytes; no EC_POINT/OID-sniff reuse — new
  parameter-set tables keyed by `CKP_*`). ML-DSA
  import assembles FLAT expanded-key PKCS#8
  (provider-witnessed decode); the provider's own
  SEQ{seed32, expanded} form is what keygen stores
  and the stamp reader parses (two shapes by
  design). `CKA_PARAMETER_SET`/`CKA_SEED` vocabulary
  (`AttrParameterSet`/`AttrSeed`, tags 49/50).
- `NativeParams.hs`: native
  `CK_SIGN_ADDITIONAL_CONTEXT` {u64 hedge, ptr, u64
  len} = 24B → canonical (header order verified
  against `spec/vendor/pkcs11.h` FIRST, the EdDSA
  field-order lesson); exact `paramsLen` gates;
  hedge bound-checked on the `Word64` before
  narrowing (no wrap smuggling).
- `Raw.hs` + `cbits`: `mldsa_sign/verify/gen`
  (LANDED), `slhdsa_sign/verify`,
  `mlkem_encaps/decaps` shims with per-set probes;
  the ML-DSA shim cross-checks the keymgmt TYPE NAME
  (provider ML-DSA keys report base_id 0 — probed —
  so the EdDSA NID check cannot work); deterministic
  rides an explicit shim flag; off-width verify
  answers mismatch without calling the provider (and
  the SAME KeyBytes lesson: sniff both
  `KeyMaterial` constructors from day one).
- `OpenSSL4.hs` + `Synthetic.hs` arms, `Driver.hs`
  dispatch + keygen, `Object.hs` import,
  `KeyManagement.hs` keygen/planner,
  `Registry.hs`/catalog/`mech_catalog.inc` rows,
  `spec/mechanisms.json` + canonical regeneration.
- HASH variants: serve exactly what the prehash probe
  proves (hash-specific rows if the provider does
  HashML-DSA; else catalog-only with named honesty
  notes — never a DIY domain separation).

## Committed tests (TDD RED first, per family)

- `RecipeMlDsaSpec` / `RecipeMlKemSpec` /
  `RecipeSlhDsaSpec`: codec roundtrips, validity
  (pure+context served, unknown sets refused),
  driver-map pins incl. `KeyBytes`-carrying-DER.
- `NativeParamsSpec`: native struct → canonical,
  wrong-length passthrough, bad-set passthrough.
- `OpenSSLSpec` / `SyntheticSpec`: KAT vectors
  (wycheproof tc1 per set), roundtrips, tamper
  negatives, cross-set refusal, cap pins.
- `OperationSpec`: NULL ADMITS for ML-DSA (struct
  optional — the opposite of EdDSA), bad hedge /
  overlong context refuse `ARGUMENTS_BAD`;
  `MechanismExhaustivenessSpec` routing.
- C: legs in `consumer_roundtrip.c` (keygen +
  sign/verify or encaps/decaps + negatives).

## Verify mapping

- Suites + 16 static gates + consumers + parity,
  then targeted PQC (wycheproof/CCTV/ACVP per
  family), fast + KAT lanes with per-unit diffs,
  triage entry, single slice commit. KEM lanes must
  also cover `test_kem.py` / `test_mech_kem.py` /
  `test_ckr_kem.py`.
- Probe results (all four closed, `/tmp/*.c` probes
  against pinned 4.0.2): (1) prehash UNSERVED —
  `EVP_DigestSignInit` with an explicit digest fails
  ("Explicit digest not supported for ML-DSA
  operations"), so all 22 `HASH_*` rows stay
  catalog-only with honesty notes (never DIY domain
  separation); (2) context 0..255 served via the
  `context-string` octet-string ctx param (sign+verify
  proven); (3) hedge PREFERRED/REQUIRED = provider
  default, DETERMINISTIC_REQUIRED = `deterministic`
  int param set to 1 (identical sigs proven); SLH-DSA
  exposes the same settable set; (4) KEM lengths
  NULL-queried: ct 768/1088/1568, ss 32 for
  512/768/1024; header shapes
  `CK_SIGN_ADDITIONAL_CONTEXT` {u64 hedge, ptr, u64
  len} = 24B and `CK_HASH_SIGN_ADDITIONAL_CONTEXT`
  {+u64 hash} = 32B, all-word (no padding traps).
