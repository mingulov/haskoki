## Discovery (proven, not assumed)

- Spike (no commit): provider DSA C probes — DONE. OpenSSL 4.0.2
  default provider: paramgen serves all FIPS pairs (1024/160,
  2048/224, 2048/256, 3072/256); pbits-only defaults q=224 for
  every size (non-FIPS for 1024 — Haskoki must set q
  explicitly). Keygen from params, raw-digest sign/verify, and
  DigestSign/Verify all OK for all 9 digests (SHA1, SHA224/256/
  384/512, SHA3-224/256/384/512 — no security-level refusal).
  Raw sign accepts ANY digest length (even 7 bytes): the 20-byte
  floor is Haskoki's to enforce. Provider speaks DER
  signatures; PKCS#11 speaks raw r||s (DER<->raw conversion at
  the shim). DER params/SPKI/PKCS#8 roundtrips OK (EC storage
  precedent holds). Seeded (verifiable) paramgen UNAVAILABLE
  (legacy `DSA_generate_parameters_ex` fails) — the FIPS 186-4
  seed/index variants stay catalog-only.
- Oracle shape (`test_dsa_complete.py`, 1245 lines): setup is
  `CKM_DSA_PARAMETER_GEN` (`CKA_PRIME_BITS`=2048, no subprime
  bits) -> domain-params object with `CKA_PRIME/SUBPRIME/BASE`
  readback -> `CKM_DSA_KEY_PAIR_GEN` (p/q/g in the public
  template) -> sign/verify. Raw `CKM_DSA`: 20-byte digests OK,
  7-byte digests refuse `CKR_DATA_LEN_RANGE` (sign AND verify),
  truncated/overlong sigs fail, random-k nondeterminism.
  Prehash x9 (`DSA_SHA1`, `SHA224/256/384/512`,
  `SHA3-224/256/384/512`): single + multipart roundtrips,
  tamper/data/sig negatives, empty input, 10 KiB input.
  Paramgen: missing `CKA_PRIME_BITS` refuses
  `CKR_TEMPLATE_INCOMPLETE`; plain gen asserts handle only.
  The 3 seed-variant tests gate on `has_mechanism` (skip when
  unadvertised — honest).
- Oracle shape (wycheproof, 1956 vectors): `import_dsa_public_key`
  (p/q/g/y by value) + `C_Verify` with raw r||s over DSA
  2048/224, 2048/256, 3072/256 x SHA-224/256 (DER and P1363
  files; the oracle converts to raw itself).
- `test_sign.py::TestDSASignature` (slow-marked: KAT-only):
  paramgen -> keypair -> `CKM_DSA_SHA256` roundtrip.
- Haskoki precedent is a full ECDSA mirror: `Recipe/Ecdsa.hs`
  (10 rows, digest stems, `sig-encoding/1`), `dsaSpecFor`-shaped
  dispatch, `SigECDSA` backend spec with `Maybe DigestAlg`,
  `Raw.ecdsaSign/Verify` shims, DER key storage
  (`importMaterial` assembles SPKI/PKCS#8 from components;
  `stampPairComponents` stamps readback attrs at keygen),
  `GenEc`/`GenRSA` planner-driver frames, multipart sign
  buffering to a single effect (DSA multipart comes free).
- No `CKO_DOMAIN_PARAMETERS` object support beyond the class
  name; no DSA crypto anywhere (only the `FamilyDsa` label).

## Design

- Shim `hsk_ossl4_dsa_sign/verify` (raw digest in, DER<->raw
  conversion inside) + `hsk_ossl4_dsa_paramgen/keygen` (explicit
  pbits/qbits; SPKI/PKCS#8/DER-params answers) + header
  contracts. Keygen-from-params imports p/q/g, refuses garbage
  as bad-key.
- FFI `Raw.dsaSign/dsaVerify/dsaParamgen/dsaKeygen` bindings
  (mirror `ecdsaSign/verify` + keygen entries).
- Engine `SigDSA { digest :: Maybe DigestAlg, encoding }`:
  raw row signs the digest directly, prehash rows DigestSign;
  20-byte raw floor enforced at the planner (XTS-floor
  precedent: Haskell + shim both check). Keygen specs
  `GenDSAParams` / `GenDSAKeypair`; capability sets, notes,
  probes. Served param pairs exactly {(1024,160), (2048,224),
  (2048,256), (3072,256)}; default q per prime bits
  {1024:160, 2048:256, 3072:256} (strongest FIPS N per L);
  off-pair sizes refuse with the RSA-bits refusal code.
- Driver: `dsaSpecFor`/`isDsaMech` sign/verify/verify-multipart
  arms (mirror ECDSA); `FxGenerateKey` arms for
  `GenDsaParams`/`GenDsaKeypair` framed args (new tags 5/6).
- Recipe `Recipe/Dsa.hs`: 10 rows + digest stems +
  `sig-encoding/1` codec (RAW/DER/empty); `RecipeDsaSpec` pins
  the driver mapping.
- Planners: `planGenerateKey` learns `CKM_DSA_PARAMETER_GEN`
  (PRIME_BITS required->incomplete; optional SUBPRIME_BITS
  honored only on FIPS pairs); `planGenerateKeyPair` learns
  `CKM_DSA_KEY_PAIR_GEN` (p/q/g required from the public
  template); `finishWork` stamps y (+p/q/g on the private half,
  whose template lacks them) via new `Der.hs` DSA parses;
  `keyPairCompatible` learns the new frames. `Signature.hs`
  raw-DSA floor: digest < 20 bytes -> `CKR_DATA_LEN_RANGE`
  (sign + verify). Domain-params objects publish p/q/g (+ derived
  `_BITS` readback) on `CKO_DOMAIN_PARAMETERS`.
- `Der.hs`: `dsaPublicDer`/`dsaPrivateDer` (SPKI/PKCS#8 from
  p/q/g + y/x) + `dsaSpkiParams`/`dsaSpkiY` readers;
  `importMaterial` learns the two CKK_DSA shapes (INCOMPLETE
  when short, INCONSISTENT when malformed).
- Synthetic: `GenDSAParams`/`GenDSAKeypair` + `SigDSA` keyed
  stubs with their own domain separator (parity, not vectors).
- Registry/catalog: 12 served rows (10 sign/verify + keypair
  gen + paramgen), flags [SIGN, VERIFY] / generate routes;
  the 3 seed variants stay catalog-only with provider-absence
  notes; regen + pin updates.
- Recipe module doc: drop `CKM_DSA*` from the deferred list
  (keep the seed variants + ML-DSA/SLH-DSA named).
